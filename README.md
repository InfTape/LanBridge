# LanBridge · Windows / Android 局域网互传

桌面项目包含完整源码和可运行文件。Windows 当前版本 1.6.4，Android 版本 1.4.0。支持首次扫码绑定、后续自动重连、手机分享后自动发送，以及默认自动启用的 Windows 11 第一层右键菜单“发送到手机”。新增双向文件夹传输，保留目录层级、空目录和空文件；使用原有加密连接，无需压缩成 ZIP。保留 Android 16 网络绑定限制兼容及前台服务启动顺序修复。

- **Windows**：C++20，纯 Win32 API 窗口与标准控件，原生 DPI 缩放、托盘、文件对话框和拖放；网络使用 Winsock2，加密使用 BCrypt。界面参考 `native-screenshot-tool` 的中文原生控件设计。
- **Android**：Kotlin + Jetpack Compose BOM 2026.09.00 + Material 3 Expressive 1.5.0-beta01，实际使用 `MaterialExpressiveTheme`、动态配色、Expressive 动效与加载组件，支持深色模式和宽屏双栏。Material 3 Expressive 当前使用 Beta API。
- **Android 16**：targetSdk 36；为满足新版 UI 库要求，compileSdk 37。最低支持 Android 12 / API 31。
- 双向文本与多文件传输、加密配对、分块传输、SHA-256 校验、进度、接收回执、同名文件保留、接收历史和重新复制。
- Windows 接收文本自动写入文本剪贴板；接收文件保存后自动写入文件剪贴板，资源管理器可直接 Ctrl+V。
- Windows 显示配对二维码，Android 使用 CameraX 1.6.2 + ZXing 3.5.4 在设备上离线识别，扫描成功后自动连接；无需 Google Play 服务或下载扫码模型。

## 使用

1. 在 Windows 双击项目根目录的 `LanBridge.exe`。
2. 在 Android 安装 `LanBridge-Android16-debug.apk`。这是可安装的测试签名 APK，不是商店正式发布包。
3. 手机和电脑接入同一局域网。Windows 默认选择真实 Wi-Fi / 以太网的 IPv4，优先有网关的网卡；VPN、VMware、Hyper-V 等虚拟网卡只供手动选择。没有可用的真实局域网网卡时，不会自动选择 VPN。如果电脑连接多个局域网，可在地址下拉框中选择与手机同网段的 IPv4。
4. 手机点击 **扫码绑定 Windows**，首次使用允许相机权限，对准 Windows 窗口中的二维码；识别成功后自动返回并连接，验证握手成功后安全保存绑定。以后打开应用会自动寻找并连接同一台电脑，Windows 重启后无需再扫码，IP 改变时会通过局域网发现更新地址。也可展开“手动输入 / 粘贴连接信息”，填写电脑地址和 **16 位配对码**，或粘贴 Windows 复制的连接信息；端口默认为 42831。
5. Android 中输入文本、选择文件，或在其他应用中“分享 → LanBridge”。从分享菜单进入后自动连接已绑定电脑，并发送文件或文本，不需要再次确认；首次使用尚未绑定时，扫码后自动发送。已有传输时，新的分享会排队等待。顶部大标语已移除，仅保留简洁的连接状态。
6. Windows 中选择文件、选择文件夹、混合拖入文件和目录，或点击发送剪贴板，也可发送编辑框中的文本。手机收到的普通文件在系统“下载/LanBridge”目录，文本可手动复制。
7. 手机接收文件夹前，在 **接收文件夹 → 选择保存位置** 中授权一个本地目录，例如“下载/LanBridge”。授权会保存，以后无需重复选择。手机发送文件夹使用 **选择文件夹 · 自动发送**，在系统选择器选定后直接发送。系统分享目录须提供相应子目录访问授权；来源不支持时，请使用应用内文件夹选择器。

Windows 接收目录为当前用户的 **下载/LanBridge**。右上角关闭按钮收起到托盘，仍继续接收；彻底退出使用托盘右键菜单。配对信息在 Windows 当前用户及手机本地安全保存，重启不会重新生成。一次连接一台手机，多个文件或根目录按顺序传输。文件夹全部校验通过后才显示为完成，并整目录写入 Windows 文件剪贴板，可在资源管理器 Ctrl+V。连续接收时剪贴板保留最后完成的文件或目录，其余内容可在历史列表中重新复制。

1.6.4 修复开机时网络尚未就绪、地址框和二维码停留在“请选择局域网 IPv4 地址”的问题。Windows 通过原生 IPv4 地址及网卡变化通知自动更新，重新打开窗口或建立连接时也重新检查；通知注册失败时每 5 秒重试读取地址。自动选择仍只使用真实局域网网卡，现存的手动选择保持不变；手动地址失效后回到可用的真实局域网地址，没有真实网卡时保留占位提示。刷新不重启传输服务、不更换配对码、不覆盖传输进度；没有有效二维码时不允许复制无效连接信息。

文件夹同名时另存为“名称 (1)”等，不合并、不覆盖原目录。传输中断时删除本次未完成目录，进程异常退出的残留在下次启动时清理；不提供断点续传。两端均需升级才能使用文件夹，旧版本之间仍可传普通文件和文本。每个根目录最多 10000 项、相对路径最多 64 层及 4096 UTF-8 字节；每段名称最多 180 个 UTF-16 单元及 255 UTF-8 字节。单文件上限 100 GiB、根目录总量上限 100 TiB，实际受存储空间限制。为保持两端名称和结构一致，遇到链接、Windows 不支持的名称或大小写冲突时报告错误，不静默改名或漏传。手机保存位置需支持创建、重命名和删除目录，优先选择手机本地存储；系统限制不能授权的目录不支持。

1.4.1 参考 `native-screenshot-tool` 的 Win32 自绘方式，将标题栏、托盘右键菜单、托盘悬停提示与普通控件统一为 Microsoft YaHei UI，启用 ClearType 并按所在屏幕 DPI 缩放；未连接局域网时的二维码占位文字也使用同一字体。标题栏保留拖动、双击最大化、边缘缩放和最小化/最大化/关闭操作；托盘菜单保留键盘操作与开机启动勾选状态。

1.4.2 将 Android 应用的双向箭头图标复用于 Windows 程序文件、标题栏、任务栏、托盘、右键发送与菜单身份包；ICO 内含 16、20、24、32、40、48、64、96、128、256 像素版本，SVG 和 PNG 源素材位于 `windows/assets`。

1.4.3 将托盘菜单和悬停提示调整为截图工具同样的 9pt 微软雅黑 UI。菜单采用相同的行高、左右文字边距与正常菜单宽度，较长文案仍自动扩展；“显示主窗口”“开机启动”使用简洁文案，勾选标记保持可见。主窗口的字号不受此调整影响。

Windows 主窗口、内容标题、按钮、标题栏、托盘菜单和提示统一为截图工具相同的 9pt Microsoft YaHei UI 正常字重，随显示器 DPI 缩放。操作按钮统一为 32 逻辑像素高；标题栏沿用相同的 36 逻辑像素高度、白色背景和窗口控制按钮，保留 Windows 11 圆角及窗口拖动、缩放、最大化行为。
内容区直接展示扫码、发送和接收三个分区；开机启动选项位于左侧配对区的“断开设备／重置配对”按钮下方。
标题栏显示“局域网互传”，启动及最小窗口尺寸为 890 × 620 逻辑像素。右侧操作按钮为 110 × 32 逻辑像素；发送输入框与接收列表高度均为 149 逻辑像素，二维码图案边长与其相同。发送框仅在文本超出可见高度时显示竖向滚动条。

1.4.4 修复 ZIP 文件右键没有“发送到手机”：Windows 压缩包同时带有 Shell 文件夹属性，菜单现在按真实 Win32 文件属性判断。ZIP 文件与普通文件均可选择发送，真实目录和混合目录选择仍隐藏菜单。仅更新菜单组件，无需重启传输主程序。

1.5.0 / Android 1.3.0 只需首次扫码绑定：Windows 用当前用户 DPAPI 加密保存凭据，Android 用 Keystore AES-256-GCM 保存绑定。手机打开应用或系统分享时自动连接；临时掉线后按 1～10 秒递增间隔重试，连续失败 30 次后暂停，可再次打开应用或点“重新连接”。主动断开会暂停当前自动重连，点击重连或新的分享会恢复。未完成的传输不会自动重发，仍需重新选择，避免产生重复文件。

手机“解除绑定”清除本机凭据；Windows“重置配对”更换凭据并撤销此前所有手机的访问，需要重新扫码。更换 Windows 用户、清除应用数据或卸载重装也需要重新绑定。绑定采用 UDP 42832 的挑战及 HMAC-SHA256 验证发现电脑，配对码不广播；发现被防火墙或 AP 隔离阻挡时，仍会尝试已保存地址。

## Windows 开机启动

勾选窗口左侧配对区底部的 **开机启动（默认收至托盘）**，或在托盘右键菜单勾选“开机启动”。实现参考 `native-screenshot-tool`，使用纯 Win32 API 写入当前用户的 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，值名为 `LanBridge`，命令为带引号的完整程序路径加 `--startup`，无需管理员权限。

登录 Windows 后程序直接在托盘运行并等待连接，不弹出主窗口。手动双击程序或点击托盘图标会显示窗口；重复的自启动不会弹窗、重启已有实例或断开现有连接。取消勾选会删除本程序的启动项，设置保存在启动项本身，不会在下次启动时自动重新开启。初次运行默认不勾选，本机按用户要求已启用。

1.6.3 的开机模式只启动主程序、托盘及传输服务，即使菜单检查记录缺失也不执行注册脚本。已注册的右键菜单继续可用；需要首次注册或修复时，在正常打开主窗口后自动检查并处理。此前 1.6.2 将检查未通过立即视为需要注册，开机阶段仍可能启动 PowerShell；本次将该路径明确排除在开机启动之外。

便携目录移动后，在新位置打开程序并勾选开机启动以更新路径；删除程序前先取消勾选。如果曾在 Windows 任务管理器中单独禁用 LanBridge 的启动项，需要在任务管理器中重新启用。开机启动只启动 Windows 程序，已绑定手机打开应用后自动重连。

## Windows 11 右键发送

1.6.2 使用 Win32 API 检查当前用户实际注册的菜单包、外部目录、菜单包 SHA-256 和证书信任。配置完整且未变化时直接跳过注册，正常启动只运行 LanBridge.exe，不启动 PowerShell、控制台宿主或编译器。首次启用、菜单被移除、菜单包更新或便携目录移动时才运行注册脚本。旧版升级后首次运行会补写原生检查记录，此后直接检查；已有证书信任时不重复申请管理员授权。菜单刷新使用原生 SHChangeNotify，手动注册也不再动态编译 C#。

完整解压 `LanBridge-Windows-portable.zip`，保留 `LanBridge.exe`、`LanBridgeShell.dll`、`context-menu` 和 `scripts` 在同一目录。打开程序后默认在后台自动启用右键发送，主窗口和托盘不再提供启用/移除按钮。已启用且目录位置、菜单包未变化时，不重复注册、不重启传输进程；后台检查成功不会覆盖传输进度。首次运行尚未信任菜单签名的电脑会弹出 Windows 管理员授权，用于信任本机生成的菜单包签名证书。证书仅加入 `LocalMachine/TrustedPeople`，不是根 CA；菜单身份包注册到当前用户。拒绝授权或便携包缺失文件时会显示失败原因，仍可使用应用内传输，修复后重启程序重新尝试。

启用后，选中一个或多个文件、文件夹或混合选择，右键选择 **发送到手机**。这是 Windows 11 第一层原生菜单；命令使用 `IExplorerCommand` 实现。手机已连接时立即发送，传输繁忙时排队；未连接时打开手机 LanBridge 自动连接，首次使用需扫码，连接成功后自动发送，不必再选一次。菜单不显示在虚拟项目或目录链接上。单次最多 1024 个选中根项目；待发送队列保存在当前 Windows 进程内，退出程序后需要重新选择。文件夹发送前先验证目录结构，接收端准备成功后才发送内容；本地读取失败时取消该目录并保持连接。网络帧写入失败时关闭连接，避免复用损坏的流。

1.3.1 修复了 1.3.0 中右键加载菜单会结束主程序、导致手机断线的问题：主程序保持独立的 Win32 进程，仅菜单 COM 宿主使用包身份。显示菜单不会重启主程序或重新配对；重复启用检查也不会反复注销同一个菜单包。

便携目录移动后，在新位置运行程序会自动更新菜单绑定路径。准备删除软件时，先彻底退出程序，再通过下方 Disable 命令注销本组件身份包，并移除由本组件添加的证书信任（会再次请求管理员授权）；之后删除便携目录。若重新运行程序，菜单会按默认行为再次启用。不会修改其他应用菜单或切换系统右键菜单样式。菜单暂未刷新时，可关闭并重新打开资源管理器窗口；系统仍缓存旧扩展时，重新登录后生效。

也可用 Windows PowerShell 执行：

```powershell
.\scripts\register-context-menu.ps1 -Action Enable
.\scripts\register-context-menu.ps1 -Action Disable
```

本地构建使用自签名代码签名证书。私钥只保存在构建用户的 `CurrentUser/My` 证书存储，未导出或打入便携包；公开 `.cer` 随身份包提供。其他电脑使用此开发签名包时同样需要授权证书信任。正式公开分发可用受信任的代码签名证书重新签名。实现依据：[Windows 11 原生菜单扩展](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/integrate-packaged-app-with-file-explorer)、[MSIX 签名证书与信任](https://learn.microsoft.com/en-us/windows/msix/package/create-certificate-package-signing)。

扫码用于首次绑定，手机仍需与电脑处于同一局域网。两端升级到支持记住绑定的版本后，首次扫码一次，以后 Windows 重启无需再扫。二维码包含配对凭据，只提供给要连接的手机。相机权限被拒绝、设备没有相机或扫码失败时，可使用手动连接。

若出现 Windows 防火墙提示，仅允许受信任的专用网络。连接失败时检查地址、同一网段、VPN 和 Wi-Fi 的客户端隔离设置。必要时用管理员 PowerShell 按需运行 `scripts/allow-private-network.ps1`；它只允许专用网络、本地子网的 TCP 42831，安装和构建过程不会修改防火墙。

Android 端使用数据同步前台服务和通知维持连接；可在应用或通知中断开。系统可能因前台服务时限或设备省电策略终止长时间后台连接，应用会显示断开后允许重新配对。传输中断的未完成文件会被清理，需要重新发送。

待发送分享由应用统一管理，旋转屏幕不会重复加入队列；分享附件时发送文件，分享纯文本时发送文本。队列保留在当前应用进程内，系统终止进程后需要重新分享；已经开始但失败的传输不会自动重试。

共享文件在开始网络传输前出现读取权限、文件已删除等错误时，仅提示发送失败，保持现有连接。文件头已经发送后的错误会断开连接，以便两端清理未完成传输；界面会保留实际失败原因。

## 构建

GitHub 仓库保存源码、资源、构建脚本与验证文档。根目录的 EXE、APK、Shell DLL 和签名菜单包由以下脚本生成，不提交构建缓存、本机 SDK 路径或签名密钥。

Windows 安装 Visual Studio 2022 / Build Tools 的“使用 C++ 的桌面开发”和 Windows SDK，然后：

```powershell
.\build-windows.ps1 -Test
```

Windows Release 使用静态 C++ 运行库，只需系统 DLL，无需 Qt、WebView 或外部界面运行时。

构建脚本同时生成原生 Shell DLL 和签名身份包，需要 Windows SDK 的 MakeAppx / SignTool。首次构建会在当前用户证书存储创建不可导出的开发签名私钥，构建本身不会启用菜单或更改证书信任。

Android 使用 JDK 17+（本机验证使用 JDK 21）、Android SDK Platform 37.0 和 Build Tools 36.0.0。Gradle Wrapper 固定为 9.3.1，Android Gradle Plugin 为 9.1.1。Android Studio 可直接打开 `android` 文件夹；或：

```powershell
.\build-android.ps1 -SdkPath '你的 Android SDK 路径' -Test
```

先构建两端后，可在 Windows 运行实际 Kotlin / BCrypt 互通测试：

```powershell
.\scripts\test-interop.ps1
```

同时验证实际 Win32 界面二维码与 Android 解码代码（指定路径的父目录须已存在）：

```powershell
.\scripts\test-interop.ps1 -QrImage "$env:TEMP\LanBridge-QR.png"
```

该测试捕获实际 Windows 二维码及切换地址后的二维码，使用生产 `QrDecoder.kt` 解码，并验证旋转画面。它不会打开相机或改写剪贴板。

ADB 真机分享测试（手机需允许安装测试 APK）：

```powershell
cd android
.\gradlew.bat assembleDebugAndroidTest
cd ..
.\scripts\test-android-share.ps1 -AdbPath '你的 adb.exe 路径'
```

该测试使用临时文件及单独的 Win32 回显服务，覆盖首次分享、旋转重建、连接后自动发送、再次分享以及多文件分享，不改写 Windows 剪贴板。测试会断开手机当前连接，完成后需要重新扫码。

## 验证范围

- Windows 原生协议集成测试：双向 Unicode 文本与文件、SHA-256、空文件、同名文件、心跳、错误配对码、目录穿越拒绝及临时文件清理。
- Windows 绑定测试：实际 DPAPI 保存/复用/重置、损坏存储拒绝、HMAC 向量及 UDP 服务；真实桌面进程重启后使用缓存凭据完成加密连接及心跳。
