# LanBridge LB01 协议

Windows 是 TCP 服务端，默认端口 42831；Android 主动连接。一个连接对应一个 Android 设备，两端均可独立发送，允许双向同时传输。无需互联网、云服务或额外服务器。默认通过扫描电脑端二维码配对，也支持手动填写地址与配对码。

二维码内容为 `lanbridge://IPv4:42831/16位配对码`，使用中等级纠错及至少四模块留白，Win32 GDI 按整数像素绘制。切换电脑地址即刷新二维码。Android CameraX 提供相机亮度数据，ZXing 离线识别，只接受经过 IPv4、端口、配对码校验的 `lanbridge://` 信息，拒绝附加用户信息、查询和片段；识别成功后自动连接，不打开外部网页。二维码中的凭据与手动连接相同，不改变 LB01 传输格式。

连接开始时 Windows 发送 20 字节：ASCII `LB01` + 随机 16 字节 salt。双方以大写 ASCII 配对码为密码，使用 PBKDF2-HMAC-SHA256（120000 次迭代，32 字节输出）导出 AES-256 密钥。首次 Windows 启动生成随机 16 位十六进制凭据，并以当前用户 DPAPI 保存至 `%LOCALAPPDATA%/LanBridge/pairing.dat`，后续启动复用；“重置配对”时更换。Android 仅在加密 Hello 握手成功后保存绑定，使用不可导出的 Android Keystore AES-256 密钥及 GCM 认证加密；偏好设置只存密文，凭据不放入 Activity 保存状态。每次连接仍使用新的随机 salt、nonce 和序号。

已绑定手机在打开应用、进入系统分享或临时掉线时自动连接，优先使用真实 Wi-Fi 网络。UDP 42832 发现请求为 `LBD1` + 16 字节随机挑战；Windows 回复为 `LBR1` + 原挑战 + uint16 大端 TCP 端口 + 32 字节 HMAC-SHA256。HMAC 密钥是配对凭据的大写 ASCII 字节，覆盖前 22 字节回复；手机使用常量时间摘要比较，仅接受匹配凭据、挑战及合法端口的回复，然后使用回复来源 IPv4 进行原有加密 TCP 握手。广播不包含配对凭据。发现失败时尝试上次地址，连续重连失败 30 次后暂停；下一次打开应用、点击重连或新的系统分享可再次尝试。主动断开会停止后台重试。

每帧为：4 字节大端长度 + 随机 12 字节 nonce + AES-GCM 密文 + 16 字节 tag。明文为 1 字节 type + payload。长度范围 29–262173，payload 最多 262144 字节。AAD 是 1 字节方向（Android→Windows=0，Windows→Android=1）+ 8 字节大端序号，双方各自从 0 累加。方向与序号绑定，阻止跨方向反射及同一会话帧重放。连接之间采用新的 salt。

| type | 内容 |
| --- | --- |
| 1 | Hello，UTF-8 设备名称，最多 256 字节；必须首先交换。新版追加换行和 `LB-FOLDER1` 表示文件夹能力 |
| 2 | UTF-8 文本，不允许 NUL，长度 1–262144 字节 |
| 3 | 文件开始：uint16 大端文件名 UTF-8 字节数 + 文件名 + uint64 大端文件大小 |
| 4 | 文件内容分块，最多 256 KiB |
| 5 | 文件结束：原始 32 字节 SHA-256；长度与摘要同时验证 |
| 6 | UTF-8 接收确认；Windows 回执区分保存成功与剪贴板复制成功 |
| 7 / 8 | 心跳请求 / 应答，无 payload |
| 9 | 文件夹开始：uint64 事务 ID + uint16 根名称 UTF-8 字节数 + 根名称 + uint32 文件数 + uint32 子目录数 + uint64 文件总字节数，整数均大端 |
| 10 | 子目录：UTF-8 相对路径，显式发送以保留空目录 |
| 11 | 目录内文件开始：同 type 3 格式，名称改为 UTF-8 相对路径；内容和 SHA-256 使用 type 4 / 5 |
| 12 / 13 | 文件夹提交 / 取消：uint64 事务 ID |
| 14 / 15 | 准备 / 完成回执：uint64 事务 ID + uint8 结果（0 拒绝、1 成功）+ 可选 UTF-8 原因 |

文件夹仅在双方 Hello 都声明能力时发送；旧端不支持时先提示升级，不向其发送未知事务。发送端预先遍历根目录，验证名称、计数和大小。接收端回复 type 14 成功后才发送内容，发送端在 type 12 后等候 type 15 确认保存；两次回执等待均为 30 秒。事务 ID 是非零、不透明的 64 位值。路径使用 `/` 分隔，必须先声明父目录；根目录不计入子目录数。路径拒绝绝对路径、`..`、空段、反斜杠、保留名称、重复及大小写冲突。每根目录最多 10000 项、相对路径 64 段 / 4096 UTF-8 字节，每段最多 180 UTF-16 单元 / 255 UTF-8 字节；单文件 100 GiB、总量 100 TiB。源目录的链接、循环或虚拟文件拒绝传输。

接收端将整目录写入本次专属临时目录，各文件验证长度和 SHA-256，提交时验证全部计数及总字节。完全成功后重命名根目录发布；已有同名根目录保留，新增目录使用递增后缀，不合并覆盖。Windows 在完成后仅将根目录写入 CF_HDROP 并记录一次历史；子文件不逐个覆盖剪贴板。Android 使用用户通过 SAF 一次授权并持久保存的目录，需要提供创建、重命名、删除能力；普通文件仍走 MediaStore。文件夹事务无需生成 ZIP 或完整缓存；只有 Android 来源未提供大小的单个文件会先缓存以确定长度。

本地源读取错误可发送 type 13，接收端关闭当前文件并删除该事务临时目录，连接继续可用。接收准备失败用 type 14 拒绝，不影响连接。异常帧、摘要错误或网络断线会结束连接并清理未完成事务；写入网络帧失败必须关闭连接，不能复用可能缺字节的加密流。Windows 为临时目录记录当前用户注册表日志，下次启动仅清理接收目录内、由本程序记录且原进程已退出的临时目录；Android 记录未完成 SAF URI，下次启动只清理仍为临时名称的记录，已发布目录不会删除。

单方向的多个文件串行传输，文本可以在接收方向独立到达。每次完成一个接收文件，Windows 自动将该文件写入 `CF_HDROP` 和 `Preferred DropEffect=COPY`；文本使用 `CF_UNICODETEXT`。多文件连续接收时剪贴板是最后一个完成接收的文件，前面的文件仍保存在接收目录和历史列表。

Windows 使用随机 `.part` 临时文件、严格文件名检查、空间检查和不覆盖的原子重命名。Android 使用 MediaStore Downloads 的 `IS_PENDING`，验证完成后才公开文件。中断或错误时删除未完成文件；不提供断点续传。同名文件保留两份。单个文件上限为 100 GiB，实际还受两端磁盘可用空间限制。

加密采用 Windows BCrypt 与 Android/JVM javax.crypto；不是 TLS。知道配对码即可连接此电脑，直至 Windows 重置配对，凭据应只提供给要连接的手机。手机“解除绑定”清除其本地保存内容，不撤销其他副本；Windows“重置配对”更换凭据，撤销所有旧绑定。没有前向保密或设备公钥身份机制。这一版本适用于受信任的家庭或办公局域网。
